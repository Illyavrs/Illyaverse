# Public announcements and management

An ordinary code-led extension of the existing Illyaverse website. The user requests a complete community site and recently called out missing functions. Add real announcement persistence and an operator publishing workflow; preserve the existing black neutral-glass world and direct multilingual labels. The user has already selected direct implementation and browser inspection; no artwork, composition tournament or identity replacement is needed.

TYPE: Existing self-hosted Nunito/Noto, restrained headings, readable body measure, real dates and clearly labelled statuses.
MATERIAL: Existing neutral glass tokens and independently adjustable panel blur, opacity and live radius. Preserve paired light appearance and keyboard focus.
GROUND: Pure black default; no new image or decoration. Public content is operator-authored text.
THESIS: Players can read published server information; staff can write, review, publish and withdraw it without exposing drafts or losing edits.
OWN-WORLD: Original code and persistent records, integrated with the existing navigation, home side column, administrative workbench and permission editor.
STORY: Homepage preview leads to a paginated public list and full text. Authorized staff create drafts, edit them, explicitly publish or withdraw, and resolve stale-revision conflicts with drafts retained. Loading, empty and error states explain the available next action.
HISTORY: Same-document browser Back/Forward may leave the editor while a globally mounted, authorized-user-scoped memory vault retains pending text and its original revision. Returning revalidates private access and the current record, shows a recovered-draft notice, and flags changed versions. Replacing or removing pending edits requires explicit discard; logout, account change or lost permission clears the vault even while the editor is absent. No browser storage or implicit API write is introduced.
FIRST VIEWPORT: The landing adds a compact announcement preview before connection steps. The public list immediately identifies announcements and their titles, authors and publication dates. The detail page leads with title/date and normal text. Administration separates record selection from editing, stacking on phones; publication is an explicit action.
FORM: Public APIs return only published records, even to staff; unpublished details are 404. Administration requires announcements.manage and panel entry admin.view. Mutations revalidate current permission/session in an audited transaction and use an expected revision. No automatic posting, outgoing notifications, HTML execution or fabricated running-server activity.

Modes: public announcements Read; administrative editing Operate; homepage preview retains its landing Persuade context. One scoped detector and one batched desktop/mobile review across locales/themes; one consolidated correction and at most one confirmation round. Native score-submission testing remains separate.

Preserve incumbent DESIGN.md and sidecar for this ordinary extension, and document the finished behavior and evidence separately. No new shipping raster is introduced.
