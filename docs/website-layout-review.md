# Community landing and public profile layout review

Reviewed on 2026-10-08. This is a code-led expansion of the existing Illyaverse visual world. The requested references informed content coverage (Sunrise) and profile information hierarchy (official osu!); the implementation retains Illyaverse's existing materials, typography, personalization and product constraints.

This review records the resulting surfaces. It does not refresh or replace the normative [DESIGN.md](../DESIGN.md) or its [.impeccable/design.json](../.impeccable/design.json) sidecar.

## Scope and product truth

The landing now connects the introduction and account/client actions to a server-status strip, recent maps, public verified scores, an osu! vanilla ranking preview, three connection steps and a permission-aware tools directory. Each data collection has its own loading, error/retry and empty treatment. Status is refreshed every 30 seconds; counts come from `/status`. The landing requests verified scores explicitly and also filters the returned collection to verified submissions.

The profile now groups mode and vanilla/RX selection, uploaded banner/avatar, identity, global/country rank, available statistics and grade counts in a shared masthead. About, best/recent scores and uploaded local maps follow as full-width sections, with in-page navigation. Best-score rows expose pp, server weighting and weighted contribution alongside accuracy, combo, mods, raw score, date, verification and replay availability. Missing values remain unavailable rather than becoming fabricated metrics.

The profile's local-map query uses the persisted uploading account (`uploaded_by`) and `source=local`; the free-text mapper field does not establish authorship or ownership. The catalogue handoff keeps those filters. Public lists retain the active-map visibility rule; administrative availability filtering remains explicit.

Message opens `/chat?recipient=…` and prefills the recipient form. Opening the profile or destination does not create a conversation or send a message; the player submits the form. Guest/owner distinctions, server permissions, score privacy, replay access, mode/RX selection, page URL state and per-resource access-error recovery remain part of the implementation.

Grade totals count verified submissions, including repeat attempts. Ranks remain unavailable without eligible pp. RX score totals remain unavailable, and incomplete vanilla totals carry explanatory copy. Rank history, measured playtime, visits, medals/achievements, published news and curated featured maps are absent because their persistence and workflows are incomplete. Native stable/lazer gameplay and stable score submission still require the separate [real-client verification](verification.md).

## Drift recorded without system repair

The preserved system documentation still describes the earlier landing body (290px sidebar, narrowing to 250px), 270px profile about column, compact introduction minimum heights and landing display line-height 1.35. The current scoped styles use the dimensions above, stacked profile sections and landing line-height 1.3. The sidecar's narrative and component previews likewise represent the earlier surface state.

Pre-existing source/document differences also account for most detector advisories: contextual type sizes exceed the narrow frontmatter ramp; the detector interprets the live-radius multiplier values as off-scale literals; existing navigation/small-label fixed corners and map-placeholder colors are not all represented as primitive tokens. The incumbent native-control font inheritance and neutral border-color cascade effects are already described in `DESIGN.md` and remain observations rather than instructions for future error states.

No advisory value, source defect or unsupported capability was added to the design system to make findings disappear. `DESIGN.md` and `.impeccable/design.json` were left untouched because this authorized task expands existing surfaces; a broader design-system refresh was not requested.
