Unimplemented endpoints must not be advertised as completed features. A successful synthetic request proves the tested server contract, not full native-client compatibility.

Native admission locks and rechecks the unrestricted score owner before the score, matches the immutable native source and ingestion key, and atomically records the first pending-to-verified transition as `scores.native_publish`. Native capture/score retries never override an explicit `scores.verify` administrator decision, including pending or rejected. Normal stable score saves no longer queue an extra saved/review Bancho notification; the original submission result carries the result. The actual stable persistence evidence is separate from validation of this publication policy and the full release checklist.

## Current source additions

These changes are implemented in source and await deployment. Historical receipts retain their original scope; actual native display, login and gameplay validation remain pending.

- Lazer score and player-ranking request builders add vanilla/RX through stock `WebRequest` query parameters, preventing malformed URLs with a second `?` when pagination/filter parameters are serialized. The `/api/v2/rankings/{ruleset}/{kind}` player route supports `performance` and `score`: score placement uses ranked score, while the returned player's `global_rank` remains the PP rank. See [bridge request builders](../tools/transfiguration/src/RelaxContext.cs) and [lazer routes](../services/resonance/src/lazer.rs).
- Room creation and playlist add/edit resolve uncached official map identities before taking mutation locks. Current session, account, permissions and room admission are rechecked after discovery and lock waits before changes are accepted. See [room discovery and admission](../services/resonance/src/signalr.rs).
- Stable sends one welcome in each successful explicit login response. The lazer bridge permits one native welcome posting attempt per login epoch after the verified private provider reaches Online; reconnect and refresh keep that epoch, and explicit sign-out permits the next login's welcome. Native presentation remains unverified. See [stable login](../services/resonance/src/stable.rs) and [lazer welcome state](../tools/transfiguration/src/SessionWelcomeState.cs).

## Stable protocol boundary corrections

The stable packet and legacy HTTP corrections are covered by focused tests. A valid empty `PING` (packet type 4) drains queued packets and does not cause an unsolicited `PONG` (type 8). The independent initial-response parser checks `cho-protocol: 19` and consumes each binary packet completely, including self ID, presence, stats, friends and channel sections. Repeated idle polls remain empty, a queued notification is delivered once, and a nonempty `PING` payload returns 400. The legacy HTTP checks cover `GET /web/osu-getseasonal.php` returning the JSON array `[]` and `GET /web/bancho_connect.php` returning an empty 200 response. The legacy country lookup is case-insensitive (`TW` → 220; unknown → 244). For an existing visible account with no avatar, the avatar endpoint returns an original opaque black 64×64 PNG and supports its ETag/304 path; unknown or restricted accounts return 404. See the [social session parser tests](../services/resonance/src/social_session_tests.rs) and [protocol smoke test](../services/resonance/tests/protocol_smoke.py).

## Nullable-ruleset lazer profile paths

The pinned stock client generates `/api/v2/me/` when `GetMeRequest` has no ruleset, and `/api/v2/users/<lookup>/` when `GetUserRequest` has no ruleset. An explicit ruleset adds its short name after that final separator. These are client-generated paths, including the trailing slash; see the original [GetMeRequest](https://github.com/ppy/osu/blob/6cbcae7fbb764839a66c1adf564c2e1679242072/osu.Game/Online/API/Requests/GetMeRequest.cs) and [GetUserRequest](https://github.com/ppy/osu/blob/6cbcae7fbb764839a66c1adf564c2e1679242072/osu.Game/Online/API/Requests/GetUserRequest.cs) at client commit `6cbcae7fbb764839a66c1adf564c2e1679242072`.

The 2026-10-09 player login reached a successful `POST /oauth/token`, then repeated empty 404 responses for the exact `/api/v2/me/` path. The retained gateway exposes the corresponding canonical route without its trailing slash. All three checked-in Caddy configurations now remove that one suffix internally only for `GET` or `HEAD` matching `^/api/v2/(me|users/[^/]+)/$`, before proxying to the same authenticated handlers. Query parameters and Authorization are preserved, with no client redirect. Explicit-ruleset paths, score paths, double trailing slashes and write methods are outside this rule. The mechanism uses Caddy's documented [URI suffix operation](https://caddyserver.com/docs/caddyfile/directives/uri).

The isolated proxy fixture passed three configuration adaptations and 696 HTTP checks, including header/query preservation, narrow matching, unchanged upstream routing and no redirect. It separately verified an internal-TLS, same-container `SIGUSR1` reload with the admin endpoint disabled; [Caddy's signal contract](https://caddyserver.com/docs/command-line#signals) describes reloading the initial file configuration. See the [fixture receipt](../.artifacts/tests/lazer-path-compat-20261009T150051Z-f1ffa6ef91e14685b1ce5ebd6b00fbd3/verification.json).

Only the retained `illyaverse-client-test` Caddy was reloaded for this hotfix. Its real HTTPS aliases and canonical routes now reach the same unauthenticated 401 response, using ordinary certificate verification and no redirect. Backend images, all ten container identities and both migration-22 databases remained unchanged. This establishes route reachability; authenticated native login after the hotfix remains pending. The [targeted reload receipt](../.artifacts/builds/integration-20261009/lazer-route-hotfix-20261009T145619Z-ab56370b579e45d385e2f587e12ae597/verification.json) and current integration record preserve the deployment boundary. Direct gateway aliases are prepared in source for a future deployment and were not deployed with this proxy hotfix.

## Official catalogue search in lazer

The default authenticated `/api/v2/beatmapsets/search` delegates official discovery to Sanctuary's existing website search cache and upstream rate budget. The previous local-only search interpreted `cursor_string` as an integer offset and ignored stock sort/feature filters. The native response now carries the upstream opaque `cursor` object as well as `cursor_string`, all original set difficulties, checksums, bounded statistics and canonical cover URLs. The pinned [search request](https://github.com/ppy/osu/blob/6cbcae7fbb764839a66c1adf564c2e1679242072/osu.Game/Online/API/Requests/SearchBeatmapSetsRequest.cs) serializes `cursor[...]`; its [response model](https://github.com/ppy/osu/blob/6cbcae7fbb764839a66c1adf564c2e1679242072/osu.Game/Online/API/Requests/SearchBeatmapSetsResponse.cs) consumes the object for subsequent pages.

Resonance validates the bearer before forwarding the bounded query through an authenticated internal service route, then rechecks it after success or failure. Sanctuary checks the service key before body parsing and rechecks the unrestricted local user after waiting. Shared discovery keeps its existing six-second deadline, cache coalescing, public-slot/cache-miss budget, fixed official upstream and global OAuth/backoff machinery. Withdrawn sets and per-difficulty private status decisions are merged using current database state. A decision changes only the selected native difficulty; mixed official sets retain their upstream label, and a set-level common label requires all members to agree. Graveyard and WIP use native ranks -2 and -1. Native set detail and local identity resolution use the same individual-status boundary. Upstream total, membership, ordering and cursor retain their original meanings; a private promotion does not alter the official service's status-filter result. Search does not ingest maps or archives. Archive downloads prefer retained complete `.osz` bytes and may use verified transient provider acquisition when configured and permitted; that transfer does not persist an import. Metadata alone without available retained bytes or permitted acquisition does not clear `availability.download_disabled`.

Official search honors nonpersonal stock mode/status/sort/genre/language/explicit/feature filters. Personal official-account filters (`mine`, `favourites`, `follows`, `recommended`, `played`, ranks) explicitly fail rather than substituting an application account for an Illyaverse player. The stock initial UI normally requests `leaderboard` plus `featured_artists`; the website's current default is Ranked, so matching filters are required when comparing results. Default search remains official. In source 28, explicit native `source=local` requires genuine uploaded local content, and the website Local tab fixes local/uploaded-only filters; these new restrictions are not yet deployed. A stock `q` beginning `server:` without an explicit source still selects the broader finite server catalogue, including validated metadata-only decisions, with effective per-difficulty membership, exact totals and opaque query/revision-bound cursors. Unfiltered public/admin catalogue APIs also retain the broader scope. This does not alter upstream Ranked membership. Clear feature/personal filters for this supported server contract; unsupported fields fail explicitly. See the current integration and native discovery contract for source/deployment/client boundaries.

The [consolidated source receipt](../.artifacts/tests/lazer-official-search-20261009T155720Z-cf12e3114b5f40cb949540442559afbd/verification-confirmed.json) binds final owned hashes, 67 Resonance units, six search/status PostgreSQL HTTP cases, Clippy and formatting. It separately preserves the preceding 13 map and 17 direct-set regressions, Sanctuary's full and final narrow proofs, failed attempts, independent review, and verified removal of the owned tmpfs database/network/context. The real stable getscores fixture confirms known Graveyard/WIP maps remain submitted-unranked `0`; lazer's `-2`/`-1` mapping does not leak into that protocol. No native game or retained deployment was executed by this search lane.

## Deployment contract

Resonance listens on `RESONANCE_BIND` (default `0.0.0.0:8081`) and shares PostgreSQL migrations with Sanctuary. Set `DATABASE_URL`, `STORAGE_PATH`, `SANCTUARY_INTERNAL_URL`, and an `INTERNAL_SERVICE_KEY` of at least 32 bytes. Sanctuary and Resonance must mount the same maps/replays storage. Only hashed protocol tokens are persisted; the website session cookie uses a separate session format.

The reverse proxy must route Bancho hosts and `/users`, `/users/`, `/web/*`, `/osu/*`, `/d/*`, `/oauth/*`, `/api/v2/*`, `/signalr/*` and `/notification-server` to Resonance. The spectator host routes `/multiplayer`, `/spectator` and `/metadata`, including WebSocket upgrades. The native chat URL comes from `LAZER_NOTIFICATION_ENDPOINT`, or the configured public origin with the WebSocket scheme and `/notification-server` path; it cannot contain credentials, query parameters or fragments. Set `ILLYA_DOMAIN` for the restricted `a.<domain>` avatar endpoint. Forwarded IPs are trusted only when the immediate socket peer is in `TRUSTED_PROXY_CIDRS`. Query strings containing stable credentials are excluded from gateway request logs. Public score JSON never includes password hashes or protocol token hashes.

Run one Resonance gateway instance for the current realtime implementation. PostgreSQL retains rooms, private-channel memberships and score-token replay capture chunks; live spectator fanout and transport queues use memory. On restart, interrupted lazer rooms close and memberships are released; room history remains available. Ended replay captures already bound to scores recover in bounded startup/periodic batches.

Players use the [Kaleidoscope launcher](/docs/clients/kaleidoscope-launcher): its GUI settings save a private HTTPS DNS origin (default `https://illya.test`) for the next launch, while a running session retains its captured origin. Stable starts with `-devserver` and requires HTTPS port 443; supported stock lazer starts with the temporary Transfiguration bridge and supports a custom HTTPS port. Official `ppy.sh` domains and fallback are refused. The GUI does not edit hosts or install certificates. Operators prepare public DNS/TLS, or isolated local DNS/CA for `illya.test`, according to the [connection guide](/docs/clients/connection). DNS or hosts routing alone does not set lazer OAuth/API endpoints or establish protocol compatibility; certificate verification remains enabled. Public deployments can use the configurable-origin package once its complete build and native validation are available.

## Native client release checklist

Record exact stable and lazer build versions when exercising these flows:

- Login, logout, reconnect, expired credentials and restricted accounts.
- Public chat, direct messages, friends/blocks, permission revocation and staff visibility.
- Download/import an official map and a private uploaded map; check osu!direct archive handling.
- Play each ruleset, submit passed/failed scores, retry after interruption, download/watch the saved replay.
- Validate supported mods and reject unsupported settings without producing misleading PP.
- Confirm normal validated native scores publish automatically, passed lazer scores await complete captures, failed stable plays remain history without passed ranking, and stable saves do not add saved/review banners. API submissions, incomplete captures and explicit administrator pending/rejected decisions must retain their privacy/state; processed room results additionally permit peers from the exact frozen round through room routes.
- Validate HeadToHead room token creation while loading, submission/retry, result display, authorized metadata statistics and ended-connection processing events.
- Validate native realtime transport negotiation, rooms, spectators, host transfer, ready/load/complete and disconnect recovery.
- Check TLS trust and reversible host changes, including restoration after the helper is removed.

Specific remaining features include stable Target Practice's extra score/replay field, in-editor map publishing, tournament interfaces, mixed stable filename/ID indexing, unsupported lazer mod settings, announcement channels and non-chat notification types. Stable and lazer currently use separate multiplayer room models. Native map score leaderboards compare reported lazer standardized totals with passed, convertible stable estimates; unsupported score scales are excluded. Stable map boards preserve their raw-score source. Shared profile totals use Classic display caches for native/ScoreV2 and raw stable V1 history; ranked totals select a standardized best result per map before adding its Classic value. PP selection remains independent. The original versioned converter is contract- and integration-tested, with actual gameplay still pending; see score normalization.

The realtime subset also excludes long polling, stateful reconnect, quick/ranked play, unsupported match types and countdown requests. Room-local aggregation remains separate from solo/global rankings. Durable solo receipts and `UserScoreProcessed` delivery now have original implementations for both bound solo and room attempts; isolated HTTP/WebSocket tests cover both completion orders and exact submitting connections. These source changes have not been deployed to retained services. Limits and statuses are enumerated in the [hub compatibility document](/docs/reference/signalr-compatibility). No native stable or lazer build has completed the release checklist above.

The installed release client contains an Auth.Loader constructor absent from the pinned public Program source. Its native startup queries RT_VERSION on the current process image, so an ordinary Rust host without VERSIONINFO crashes before GameHost.Run. The existing matching dump and static native provenance are recorded in the 2026-10-09 checkpoint. Kaleidoscope embeds its own launcher identity and version resource; it does not remove the Auth loader. The successful original draw callback follows swap but schedules window visibility asynchronously, so a first-frame checkpoint alone does not certify OS visibility, login or gameplay.
